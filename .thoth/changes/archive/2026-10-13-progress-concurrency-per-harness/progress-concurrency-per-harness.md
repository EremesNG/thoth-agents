# Change: progress-concurrency-per-harness

**Classification**: substantial
**Scope**: cross-cutting
**Uncertainty**: low
**Risk**: medium

## Exploration

- `src/agents/prompt-sections.ts:535` renders one shared root sentence for every
  harness: "create items up front, keep one in_progress, complete each
  immediately". The progress tool name is injected from the dialect
  (`src/agents/prompt-dialects.ts:148` OpenCode `todowrite`, `:184` Codex
  `functions.update_plan`, `:237` Claude `TodoWrite`, `:284` Pi `todo`).
  `ToolNomenclature` (`prompt-dialects.ts:20-30`) carries only `progressTool`.
- `skills/thoth-sdd/SKILL.md:91-96` says "Keep the current stage as the one item
  in_progress"; `implement.md` has no progress-status rule.
- Generated copies: `plugin/agents/orchestrator.md:15` and
  `plugin/skills/thoth-sdd/SKILL.md`, regenerated by `pnpm run build`
  (`integration:sync`). Pi root is rendered at runtime (`src/harness/adapters/pi.ts`).
- Pins: `src/agents/prompt-rendering.test.ts:825-840` asserts the same exact
  sentence for all four dialects; `:873-925` SHA snapshots for OpenCode, Codex
  and Claude role prompts; `:855-868` strict root caps with headroom OpenCode 253,
  Codex 267, Claude 300, Pi 247 characters. `src/harness/bundled-skills.test.ts:212`
  pins "one item in_progress".
- Pi `todo` has no in_progress limit (`.thoth/specs/pi-ecosystem/spec.md:21`).
  External evidence (librarian): Codex `update_plan` description says "At most one
  step can be in_progress at a time" (guidance, not enforced); OpenCode
  `todowrite` says "Only have ONE task in_progress at any time" (guidance, not
  enforced); Claude Code `TodoWrite` official docs did not settle it.
- No canonical spec requires exactly one in_progress item.

## Intent

The root prompt and the thoth-sdd skill state progress-status concurrency per
harness: Pi marks every concurrently active delegated unit or task in_progress,
because its `todo` tool supports it and Thoth runs units in parallel; OpenCode,
Codex and Claude keep one in_progress item, honoring their native tool guidance.

## Non-goals

- No change to the Pi `todo` extension, child prompts, or delegation lifecycle.
- No runtime enforcement of progress status in any harness.
- No change to the pre-implementation stage list or one-list-per-change rule.
- No raising of root character caps.

## Acceptance

- AC-1: The rendered Pi root prompt tells the root to mark every concurrently active unit in_progress, while OpenCode, Codex and Claude roots still say to keep one in_progress; all four roots stay below their existing caps.
- AC-2: The canonical and plugin thoth-sdd SKILL.md state that Pi `todo` may hold several in_progress items for concurrently active stages or tasks and that `TodoWrite`, `todowrite` and `update_plan` keep one, with the plugin copy byte-identical.
- AC-3: The record declares an archive-ready ADDED requirement with a scenario for the per-harness progress-concurrency rule, bound to the reviewed `multi-harness-agent-pack` baseline digest.

## Clarifications

- Per-harness rule chosen by the user (2026-10-13): Pi allows several in_progress items; other harnesses respect their native tool guidance.
- Change order chosen by the user: validator fix first (committed 47db416), then this change.

## Decisions

- SDD-DECISION: Claude `TodoWrite` keeps one in_progress item. Official docs were inconclusive; its shipped tool description asks for one active task, and the user chose to respect native limits outside Pi.
- SDD-DECISION: Add a dialect-owned progress-status phrase next to `progressTool` in `ToolNomenclature` instead of hardcoding per-harness branches in `prompt-sections.ts`; the default phrase keeps the single-item wording.
- SDD-DECISION: The shared skill text names the per-harness rule inline because one skill file serves every harness.

## Durable deltas

- `ADDED multi-harness-agent-pack` **Match progress concurrency to the native tool** — Root instructions and the bundled SDD skill MUST let the Pi root mark every concurrently active unit or task in_progress in its session task list, and MUST tell OpenCode, Codex and Claude roots to keep one in_progress item in their native progress tool.
  - GIVEN a Pi root and an OpenCode, Codex or Claude root; WHEN their root instructions and the bundled SDD skill are rendered; THEN the Pi guidance permits several concurrent in_progress items and the other harnesses keep one.
