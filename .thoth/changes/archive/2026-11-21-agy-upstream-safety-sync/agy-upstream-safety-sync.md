Compaction/rotation (`59376a7`, `806e712`, `79f8cde`, `ec307b5`) is deferred to a separate change by user decision.

## Intent

Port the safety-relevant upstream fixes so that, on agy >=1.5.11 under both ACP and stream-json: every native file write/edit (including `write_file` and current argument shapes) passes the Pi approval gate when the gate is enabled; a missing or unusable expected owned hook fails closed and visibly; ACP turns whose native tool failed never settle as an empty success; and an OK turn that is only an account-quota notice surfaces as a retryable provider error.

## Non-goals

- Compaction, rotation, helper-call isolation, occupancy-total fixes and default-on handoff digest (separate later change).
- Agent-directory path resolution (`8dee43b`), ACP session startup timeout (`f6fb22d`), installer fixes, Gemini 4 Neon catalog work.
- Changing the headless `run_command` guard semantics, the stream-json 429 carrier retry, package versions or releases.

## Acceptance

- AC-1: The approval hook is consulted for every agy native tool and is allow-by-exception: only an explicit allowlist of read-only native tools (derived from the agy 1.5.13 `init` tool inventory and recorded in source), bridge/foreign MCP tool calls (identified by positive MCP evidence in the hook payload), and `run_command` only while the separate guard is verified-delivered (its group and handler read back in the same delivery location and pre-dispatch check as the edit gate) pass without approval; when the guard is expected (its activation predicate `isRunCommandGuardActive` is true) but cannot be verified, the verified edit-gate handler itself denies `run_command` with the same Pi bash redirect reason (`formatRunCommandGuardReason`), independently of Pi approval settings including `approvals.mode=allow`; only when the guard is intentionally inactive does `run_command` require Pi approval like any other non-allowlisted tool; every other native tool — including `write_file`, `sed_file`, `notebook_edit` and any unknown future tool — requires Pi approval. Mapping recognizes the agy 1.5.11 `Path/Content` and `Path/Target/Replacement` argument shapes while keeping legacy fields. Approval is offered only for an absolute target path, which is exactly the path agy will mutate; a known write/edit tool whose target is relative, missing or unresolvable is denied; an unknown tool is presented for approval as an unknown-target operation showing its raw arguments through a production Pi-registered approval shadow whose schema carries the raw tool name and arguments (no fabricated path or command), and the Pi decision (allow or deny) is returned to agy; neither is ever approved against a guessed path; the production approval endpoint (`src/mcp-server.ts:475–528`) forwards unknown native tools to the provider park instead of rejecting names outside the old finite set, proven by a test through the real POST-to-Pi approval path; a stream-json regression uses production `--add-dir` ordering; unresolved/blank paths and empty multi-edits are denied; ACP diff handling covers `write_file`. Workspace-group ownership reconstruction and sweeping keep recognizing groups written with the historical (pre-change) matcher, proven by a fixed literal pre-change fixture rather than one generated by the current builder.
- AC-2: Gate intent is latched from configuration before any staging; with the gate enabled, no agy turn is dispatched on either carrier unless a usable owned edit-gate hook group is verified for that instance (ACP: merged into the private ACP home `config/hooks.json`, preserving foreign hooks, isolated per instance, cleaned up with the home; stream-json: the bridge hooks file must contain the owned group, not merely exist). "Usable" means both the owned group and the instance-owned handler script it references exist, are readable and match this instance. The owned handler always emits a verdict before the group's declared agy hook `timeout` elapses (no-verdict soft-pass prevention): it forwards a valid Pi decision (allow or deny) when one arrives in time, and defaults to deny on any failure or when no valid decision arrives by its internal deadline, with one overall deadline covering stdin reading and every bridge wait, proven by spawning the handler with stdin held open and asserting it emits deny before the declared timeout; the residual crash/kill case is documented. Gate staging failure, an unavailable bridge, a missing or malformed owned group, a missing or mismatched handler, or an ACP `AGY_AGENTS_ROOT` legacy override that bypasses home staging each refuse the turn with a visible error before either carrier sends a prompt. Stream-json MCP-home staging failure keeps its existing additive-configuration fallback, because gate delivery on stream-json uses the separate bridge `--add-dir` and is verified independently. Exactly one `run_command` guard remains; with the gate enabled it is delivered and verified alongside the edit gate (ACP private home; stream-json bridge add-dir), and a missing or unusable expected guard makes the edit-gate handler deny `run_command` with the Pi bash redirect, even under `approvals.mode=allow`; an intentionally disabled gate keeps current (including legacy) behavior.
- AC-3: An ACP turn that is not aborted, ends with a known-OK or unknown stop reason, has a tool failure of positively identified native provenance and produces no model text settles with a visible diagnostic that names the failed native tool, states a fixed generic failure message and points to where the agy logs hold the detail, and never includes free-form failure text from agy; unknown stop reasons are logged. Native provenance requires positive evidence from the tool start/update record (a known native agy tool name/kind), never mere absence of an `mcpServer` marker; failures of unknown provenance, MCP failures (including metadata-less foreign MCP failures), and turns with model text are unchanged.
- AC-4: A non-aborted OK handle on either transport whose only output is an account-quota notice settles as a provider error with Pi-retryable rate-limit wording (no `quota exceeded`/billing wording) at both the main settlement and the late-result redelivery settlement, classified before fallback output or any binding/watermark mutation, so an existing binding is never deleted or replaced even when the outcome carries a changed conversation ID; ordinary text that discusses quotas, turns with tool activity, and the existing 429 carrier retry are unchanged.
- AC-5: Before implementation, two minimal live stream-json probes on the installed agy 1.5.13 (launch arguments as built by `src/driver.ts`, a deny-always owned PreToolUse hook delivered through the bridge `--add-dir`), one with an isolated MCP home and one without, establish whether a hook denial is honored and the target file stays absent; the result selects the stream-json delivery branch in Decisions.
- AC-6: After implementation, one minimal live ACP probe on agy 1.5.13 through the built bridge shows the edit-gate hook delivered via the private home intercepts a native write, a completed Pi denial is observed (not a pending approval), and before/after state of the actual absolute target path shows it unchanged.

## Decisions

- Deliver the ACP edit gate through the private home `config/hooks.json` merge (upstream's live-verified mechanism) rather than relying on `--add-dir` hook discovery, which is unverified on agy 1.5.13. With the gate disabled the `run_command` guard keeps its current delivery; with the gate enabled it moves alongside the edit gate (see guard exemption decision). Exactly one guard is active.
- User decision (2026-11-21): approval-by-default with a read-only allowlist rather than a finite mutator list; unknown native tools require approval.
- User decision (2026-11-21): hook no-verdict soft-pass is handled by making our handler always emit a verdict strictly before the agy hook `timeout` — the Pi decision when a valid one arrives in time, otherwise deny — declared in the owned group (with margin, asserted by test); the residual — the hook process crashing or being killed before it writes a verdict — is accepted and documented in the README and CHANGELOG as a known limitation.
- Effective target: approval uses only absolute paths taken from the tool arguments; relative or missing targets are never resolved against a guessed base directory. cwd/add-dir routing changes are out of scope.
- Guard exemption is conditional on verification: with the gate enabled, the single `run_command` guard group is delivered in the same location as the edit gate (ACP private-home `config/hooks.json`; stream-json bridge `--add-dir`) and verified (group + handler) in the same pre-dispatch check; the approval handler exempts `run_command` only when that verification succeeded for this instance; if the guard is expected but unverified, the edit-gate handler denies `run_command` with the guard's Pi bash redirect regardless of approval settings (preserving the canonical headless guard requirement); if the guard is intentionally inactive, `run_command` requires Pi approval. Gate-off behavior, including current guard delivery, is unchanged.
- "Expected" owned hooks are determined from latched configuration intent (gate enabled), set before staging, not from staging success or file existence. Delivery is verified before dispatch on both carriers by reading back the owned group and checking the referenced instance-owned handler script.
- Stream-json delivery branch, selected by AC-5 evidence: if both probes honor the denial with the target absent, stream-json keeps `--add-dir` delivery; otherwise stream-json also delivers the owned group through the staged home `config/hooks.json` (verified like ACP), and a gated stream-json turn whose home cannot be staged is refused visibly. The probe result and chosen branch are recorded in Exploration before unit 2 starts; a branch change is in-scope and needs no new review unless it alters acceptance.
- Legacy cleanup keeps a pinned copy of the historical matcher so stale pre-change workspace groups are still recognized and swept; the live matcher is extended separately.
- Gated ACP under a legacy discovery override that cannot deliver via the private home is refused visibly (fail closed); gate-off legacy behavior is unchanged. This is a deliberate exception to ACP/stream-json tool-surface parity and is stated in the durable delta.
- User decision (2026-11-21, after final verification round 5): the native-failure diagnostic omits free-form failure text entirely (tool name, fixed generic message, pointer to agy logs) instead of pattern-based redaction, which repeatedly missed credential encodings.
- Native-failure provenance is positive-only: a known native agy tool identity from the start/update record; unknown provenance is treated as non-native (no diagnostic).
- Quota classification is shared final-outcome logic for both transports and both settlement sites (main and late-result redelivery), evaluated over the whole underlying handle (not reset at parked/replay delivery boundaries) and applied before fallback output or binding mutation. Wording follows the upstream normalized rate-limit message, which the installed Pi 1.6.0 `retry.js` classifier accepts.
