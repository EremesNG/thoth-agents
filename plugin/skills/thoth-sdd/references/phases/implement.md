# Implement

Use the settled small request or authorized substantial record, exact mutable
bounds, and focused checks. Root owns user decisions and acceptance. Keep one
writer per surface. No process tools, wrappers, reports, or temporary artifacts.

## Choose ownership, then bound the outcome

- Root retains known low-risk mechanical work, including reviewed commits;
  inspect the relevant diff/index, check it, commit, and stop. Do not restart
  exploration, planning, delegation, or full tests for an unchanged reviewed tree.
- Explicit direct-work or no-delegation instructions win. Otherwise delegate for
  a concrete discovery, implementation, parallelism, or judgment benefit. Another
  targeted search or file count does not force a new agent.
- Preserve operator-selected model and effort, including max. Efficiency comes
  from bounded work and supervision, not changing those settings.
- Each assignment delivers one independently checkable outcome. Supply exact
  known entrypoints and skill paths, accepted inputs, owned writes, focused
  checks, non-goals, and a return/stop condition. Do not delegate an entire broad
  integration without intermediate accepted outcomes or split by file count.

## Work until the outcome is satisfied, not until time runs out

- Start with supplied evidence. Read further only to answer a specific missing
  fact; do not rediscover unchanged facts or search the user home for known skills.
- Behavior changes use focused red -> green tests. Batch independent short reads
  or checks where supported. Stop cleanup at the assigned outcome's boundary.
- After two consecutive attempts without new evidence or progress, return the
  partial result and smallest blocker. Escalate a missing interface or ownership
  conflict before expanding scope. Productive long work is not failure by time.
- Root responds to native attention or a missed agreed milestone: inspect the
  delta and next action, then continue concretely, narrow, or stop safely. A long
  timeout is a safety ceiling, not a progress plan. Do not merely extend it.
- Use native completion notifications/waits, never polling, custom timers, or
  scheduler tools. Without attention delivery, bound an assignment to return at
  an agreed milestone. Reconcile termination before assigning a replacement.

## Finish once, with fresh evidence

- Freeze relevant inputs before final validation. Reuse fresh checks for unchanged
  inputs; rerun only checks invalidated by edits. Consolidate whole-project checks
  after integration, not in every child. Report known external failures rather
  than repeatedly rerunning identical checks without changed prerequisites.
- Reconcile owned background commands before returning. The final handoff includes
  the actual outcome, changed surfaces, checks, limitations, and next action. A
  late notification must preserve that handoff, not replace it with an acknowledgment.
- Final independent review remains separate. If explicitly prohibited, report
  root-only checks and leave independent PASS/archive unavailable; no self-approval.

These are instruction-level safeguards, not a runtime scheduler or latency guarantee.
