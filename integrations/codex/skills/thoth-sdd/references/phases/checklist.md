# Checklist contract

**Owner**: root<br>
**Output**: `checklists/requirements.md`<br>
**Activation**: high risk, compliance sensitivity, or ambiguity-prone scope

Use `CHK###` items and audit the requirements—not the implementation—across
Completeness, Clarity, Consistency, Measurability, and Coverage. Map every story,
FR, SC, actor, failure mode, and non-functional constraint to checklist evidence.
Record initial validation and a separate revalidation after clarification or
planning changes. Unresolved high-risk gaps return to specify; checklist status
must never be inferred from code tests.
