## Intent

Reduce the root's initial context spent on in-repo Pi tool definitions by compacting schemas and repeated prose and by omitting the provider-only `antigravity` replay declaration from requests, without changing tool names, accepted inputs, execution behavior or the substance of model guidance.

## Non-goals

- thoth-mem tools (handled in the thoth-mem project) and third-party packages (pi-web-access, @upstash/context7-pi, @narumitw/pi-goal, pi-codex-image-gen).
- The Pi-core codemode description suffix.
- Changing any tool's exposure to `deferred`/`codemode`, or deferred tool loading in pi-claude-bridge.
- Reducing or loosening ask_user_question label keys or their validation.
- Disabling AskAntigravity or AskCodex (user configuration).
- Version bumps, releases or syncing the main checkout.

- AC-2: pi-background-tasks serialized definitions are at least 2,000 characters smaller than 13,605 with repeated prose compacted, shell guidance still stated in both spawn and watch, the seven standalone tool names and their parameters unchanged, the guidance-contract tests still asserting their substance, and the budget lowered to the new measured size plus at most 5% headroom.
- AC-3: the `antigravity` replay wrapper stays registered and active and replay round trips behave as before while provider requests omit its declaration; AskAntigravity prose is compacted without parameter changes; the package budget is lowered to the new measured size plus at most 5% headroom.
- AC-4: pi-todo states the batch ref semantics once and compacts its description, snippet and guidelines without changing accepted inputs or validation, and lowers its budget to the new measured size plus at most 5% headroom.

- AC-7: pi-askcodex compacts description, guideline and parameter prose without changing parameters or `model-only` exposure, and lowers its budget to the new measured size plus at most 5% headroom.
- AC-8: the local closeout gate passes: every touched package's `typecheck` and `test` through `pnpm --filter`, plus root `pnpm run check:ci` and `pnpm run typecheck`.

## Clarifications

- Watch conditions: the user chose one flat schema with complete runtime validation over keeping the strict union (2026-10-23).
- ask_user_question labels: the user chose to keep all 46 keys and only consolidate repeated text.
- Additional exposure levers (deferred bg tools, Claude-bridge deferred loading): the user chose none for this change.

## Decisions

- No `$ref`/`$defs`: provider and Pi acceptance is unverified, and pi-questions-user already forbids serialized `$ref`.
- Hide the replay wrapper through its own `prepareLoadout` returning `hiddenDeclarations: ["antigravity"]`; deactivation and `exposure: "hidden"` both break replay.
- Shell guidance stays in both spawn and watch, as the canonical requirement demands, and is only shortened.
- Budgets are lowered to the measured size plus at most 5% headroom and never raised; each test keeps its existing baseline-ratio assertions.
- AC-1 and AC-3 change behavior and are implemented test-first; text-only compaction relies on the existing contract and budget tests.
- Prose compaction removes repetition and filler, never a behavioral constraint the model needs (defaults, limits, no-fallback, ownership, anti-error-swallowing, no-polling).

## Durable deltas

- `MODIFIED pi-ecosystem` **Compact model-facing Pi tool definitions** — The in-repo Pi packages pi-background-tasks, pi-questions-user, pi-todo, pi-antigravity-bridge, pi-askcodex and pi-subagents MUST keep each package's serialized tool definitions (name, description, parameter schema, prompt snippet and guidelines) within a size budget enforced by a package test, state shared guidance once per tool, and declare no deprecated parameter aliases; pi-background-tasks MUST expose the standalone tools `bg_task_spawn`, `bg_task_watch`, `bg_task_list`, `bg_task_status`, `bg_task_log`, `bg_task_stop` and `bg_task_clear` and no action-wrapper tools, and MUST declare `bg_task_watch` conditions with one flat condition schema whose per-type fields are validated before launch; pi-antigravity-bridge MUST keep its `antigravity` replay wrapper active and executable while omitting its declaration from provider requests.
  - GIVEN a Pi session with these packages loaded; WHEN their registered tool definitions are serialized and a provider request is prepared; THEN each package stays within its tested budget, no definition declares `maxBytes`, `tail_lines` or an `effort` alias, the background-task tools are exactly the seven standalone tools with shell guidance stated once per tool, a watch condition missing its per-type field is rejected before launch, and the request declares no `antigravity` tool while provider-emitted replay calls still execute .

## Plan

- Work splits by package; each package is one mutable surface with one writer. pi-background-tasks runs sequentially (AC-1 then AC-2, same writer files); the other five packages run in parallel with it.
- pi-background-tasks (AC-1): replace the two inline unions with one flat `Type.Object` condition schema (`type` as a string enum of the five kinds; optional `equals: number`, `value`, `path`), keep the TypeScript discriminated union in `src/types.ts`, and extend `validateCondition`/launch validation (`src/conditions.ts`, `src/runtime.ts:347`) to reject a missing or mistyped field per type (`exit_code` needs numeric `equals`; `stdout_contains`/`stderr_contains` need string `value`; `json_path_equals` needs `path` and `value`; `json_path_exists` needs `path`) and to keep JSON-path grammar validation. Tests first: one rejection per type plus unchanged evaluation of valid conditions.
- pi-background-tasks (AC-2): compact `CursorFields`, `IntentFields`, `CommandFields`, the JSON-path and shell guidance text, `WATCH_CHECK_GUIDANCE` and spawn guidelines; update `src/e2e.test.ts` phrase assertions only when wording changes, preserving each asserted behavior; lower the budget.
- pi-antigravity-bridge (AC-3): add `prepareLoadout` to the wrapper definition returning `hiddenDeclarations: ["antigravity"]`, confirm against the package's Pi type version, test that the definition hides itself while staying active and that the existing replay round-trip tests pass; compact AskAntigravity prose; lower the budget.
- pi-todo, pi-questions-user, pi-subagents, pi-askcodex (AC-4 to AC-7): text and schema-representation compaction with existing validation and contract tests unchanged except budgets and wording pins.
- Root runs AC-8 after all units are accepted, then requests a fresh read-only Oracle final verification. Live confirmation (pi-context-view after syncing the main checkout and `/reload`) is a post-closeout user check, not an acceptance gate.
- Risks: a model might send malformed conditions more often once the schema is flat (mitigated by clear launch errors); `hiddenDeclarations` semantics depend on Pi 1.4 (stop if the package's Pi types lack it); prose cuts could weaken guidance (mitigated by the constraint list in Decisions and Oracle review).
