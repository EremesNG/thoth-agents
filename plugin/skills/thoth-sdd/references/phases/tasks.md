# Tasks

For substantial work, record only useful implementation slices in the same ID-named record. `tasks` and `ready` gates require every accepted outcome to have concrete task coverage; planning does not. Each slice has one independently checkable outcome, exact known entrypoints and skill paths, accepted inputs, owned writes, focused checks, and a return/stop condition. Split broad integration by useful outcomes, not by file count or mandatory agent phases. Set a meaningful native progress milestone; do not substitute a generous timeout. Preserve operator-selected model and effort. Test-first for behavior changes. Refine technical detail within accepted intent; a material scope or risk change returns to understanding and classification. Native harness owns liveness and waits. Keep one writer per surface and no scheduler, sidecar report, process tool, execution wrapper, or temporary artifact.
