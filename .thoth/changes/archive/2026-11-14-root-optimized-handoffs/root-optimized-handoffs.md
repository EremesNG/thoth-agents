# Change: root-optimized-handoffs

**Classification**: substantial
**Scope**: cross-cutting
**Uncertainty**: low
**Risk**: medium

## Exploration

- Root sections come from `createOrchestratorPromptSections` (`src/agents/prompt-sections.ts:188-259`); specialists share `childSections` (`:294-363`). Section order is shared across the four dialects.
- Root has no response-length rule. Specialists carry only "Be concise. Return distilled evidence and outcomes, not raw logs or full-file dumps." (`src/agents/prompt-sections.ts:466-467`), which gives no concrete compression rule.
- Ordinary result contracts enumerate fields without omission rules (`src/harness/core/agent-pack.ts:409-433,499-521`): Explorer/Librarian `conclusion, evidence, verification, risks, openQuestions`; Oracle adds `nextAction`; Designer/Worker add `nextAction, changedFiles`. Observed effect in this session: 10-15k character human-formatted reports with filler in mandatory fields.
- Pi inserts the complete child result into the root context (`pi-packages/pi-subagents/src/render/completion-message.ts:99-117,152`).
- Oracle gate envelope (`src/harness/core/result-contract.ts:17-95`) requires every top-level key; the delivered gate verdict carries validity/verdict/binding but no semantic blockers (`skills/thoth-sdd/scripts/validate-result.mjs:389-402`); a REJECT without findings is structurally valid.
- Prompt size caps are repository test budgets, not harness limits (`src/agents/prompt-rendering.test.ts:797-806,1054-1069,1144-1157`; `src/agents/index.test.ts:220-229`). Headroom: roots 8-19 characters; Pi Oracle 67.
- Verified duplicates available as funding: root "No auxiliary process tools…" (132, duplicated by `skills/thoth-sdd/SKILL.md`), root identity sentence repeating the ownership default rule (~140, `src/harness/core/agent-pack.ts:276-279`), root format-only repair clause (~81, runtime-enforced); Oracle "Do not create coordination artifacts." (37) and "Reject self-review…" (95), both repeating its read-only independent role.
- Pins: inline SHA snapshots and aggregate hashes in `src/agents/prompt-rendering.test.ts:1073-1141`; generated mirrors under `plugin/codex-hooks/payloads/`, `plugin/agents/`, `plugin/.claude-plugin/.thoth-agents-plugin-assets.json`, `pi/agents/`, `pi/.thoth-agents-assets.json`, regenerated by `pnpm run integration:sync`.
- External guidance (OpenAI GPT-5.2 prompting guide, Anthropic prompting best practices): concrete length targets, positive format instructions, separate final-answer shape from progress narration; concision can reduce answer quality, so work depth must be exempted explicitly.

## Intent

Cut model verbosity across all four harnesses and make specialist results serve the consuming root model rather than a human reader: the root replies concisely to the user, specialists return terse decision-ready handoffs without filler, and Oracle rejections are actionable.

## Non-goals

- No Eco mode, model-profile or routing-tier work.
- No harness-native verbosity settings (`model_verbosity`, `textVerbosity`, output styles).
- No change to the gate result schema, validator, delivery verdicts or record binding.
- No change to Oracle routing policy ("artifact-backed", "root decides or asks Oracle").
- No change to specialist memory receipts or the thoth-mem contract.
- No hard size ceilings and no runtime truncation.

## Acceptance

- AC-1: Every root prompt in the four dialects contains one shared output-style section that requires answer-first replies, a default length target, no tool-call narration beyond brief phase or plan-changing updates, and states that brevity never reduces work depth, evidence, verification or required contract and gate fields; it also tells the root to use child answers and anchors directly and request only missing decision-critical evidence.
- AC-2: Every specialist prompt in the four dialects replaces the current response-budget sentence with a shared root-reader rule: terse `key: value` lines, answer first, evidence anchors and uncertainty kept, repeats, logs and empty non-gate fields omitted, a soft size target where completeness wins, gate JSON unchanged.
- AC-3: Ordinary (non-gate) result field lists mark optional fields per role and state that empty optional fields are omitted: Explorer/Librarian `conclusion, evidence, verification?, risks?, openQuestions?`; Oracle advice adds `nextAction?`; Worker/Designer `conclusion, changedFiles?, verification?, evidence?, risks?, openQuestions?, nextAction?` with implementation results required to report checks or why they were not run.
- AC-4: Oracle gate guidance requires each blocking finding to carry anchor, violated requirement, consequence and smallest repair inside the existing envelope fields, and the plan-review and final-verification guidance used by the root states the fixed question for each mode; the result schema and validator are byte-identical to before.
- AC-5: All prompt caps hold; any cap raised is raised by no more than the net growth left after applying the verified duplicate trims, with a justification comment; hash pins and generated mirrors are regenerated and `pnpm run check:ci`, `pnpm run typecheck`, the focused prompt suites, `pnpm run integration:verify` and `pnpm run build` pass.

## Decisions

- Root rule lives in a new `output-style` tagged section inside `createOrchestratorPromptSections`; specialist rule replaces the existing response-budget renderer text. No new sections for specialists.
- Draft root wording (worker may tighten, not weaken): "Lead with the answer or outcome; no preamble, restated request or closing recap." / "Default reply: ≤6 sentences or ≤5 bullets; longer only when content demands it." / "No tool-call narration; update only at phase starts or plan-changing facts, 1–2 sentences." / "Brevity governs prose, never work depth, evidence, verification or required contract/gate fields." / "Use child answers/anchors directly; request only missing decision-critical evidence. Do not restate reports."
- Draft specialist wording: "For root LLM: terse key: value; answer first. Keep evidence anchors/uncertainty; omit repeats, logs, empty non-gate fields. Aim ≤2k chars; completeness wins. Gates: unchanged JSON."
- Omission means "not supplied", never "verified safe": unknowns and unrun required checks stay explicit. Root acceptance rules are unchanged.
- Funding order: apply the verified duplicate trims listed in Exploration first; raise a cap only for the remainder. The proactive memory sentences and SDD workflow sentences in the root are not trim candidates. The "at most one format-only repair" rule itself stays (canonical requirement "Structured specialist results"); only its redundant runtime-enforcement aside may go.
- Fixed Oracle mode questions live in the skills the root already loads for those phases (`skills/plan-reviewer/SKILL.md`, `skills/thoth-sdd/references/phases/verify.md`), not in the root prompt. The anchored-finding rule lives in the Oracle return contract text.
- Canonical "Keep discovery roles evidence-only" froze Oracle and Worker/Designer handoffs as unchanged; it is modified narrowly to allow omitting empty optional fields while keeping role boundaries and field sets.
- The new delta does not overlap canonical "Structured specialist results": that requirement keeps "compact fields judged by root" for ordinary results and is unchanged.
- Gate schema stays v1; blocking findings go in `risks[].description` with `evidenceIds`; `nextAction` names owner/routing without repeating findings.

## Durable deltas

- `ADDED multi-harness-agent-pack` **Root-optimized handoffs and concise output style** — Every root prompt MUST carry a shared output-style rule requiring answer-first, length-bounded replies without tool-call narration, and MUST state that brevity never reduces work depth, evidence, verification or required contract and gate fields. Every specialist prompt MUST direct ordinary results at the root model as terse labeled lines with evidence anchors and explicit uncertainty, MUST omit empty optional fields, and MUST treat size targets as soft with completeness taking priority. Oracle gate results MUST keep the validated envelope unchanged and MUST express each blocking finding as anchor, violated requirement, consequence and smallest repair.
  - GIVEN a root or specialist prompt rendered for any supported harness; WHEN the prompt is inspected; THEN the root contains the shared output-style rule, the specialist contains the root-reader handoff rule with optional-field markers, and the Oracle gate envelope contract is unchanged.
- `MODIFIED multi-harness-agent-pack` **Keep discovery roles evidence-only** — Explorer and Librarian MUST return facts with evidence and, when non-empty, verification, risks and open questions only, MUST NOT recommend fixes, designs, defaults or next actions, and MUST escalate an open question it cannot settle as the question with its possible options and the facts for each option without choosing one. Oracle judgment and Worker/Designer implementation handoffs MUST keep their role boundaries and field sets, MAY omit empty optional fields in ordinary results, and every harness MUST render the same role-specific return contract.
  - GIVEN an Explorer or Librarian assignment that ends with findings and an open choice it cannot settle; WHEN the specialist returns in any harness; THEN its return lists facts and the open question with options and their facts, omits empty optional fields, contains no recommendation or next action, and root decides or asks Oracle.
